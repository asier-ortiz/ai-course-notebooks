1. Comprensión del Negocio (CRISP-DM - Fase 1)

1.1. Contexto y motivación

El mercado de alquiler en Madrid presenta un problema evidente: encontrar vivienda asequible se ha convertido en una tarea extremadamente compleja. Definimos "alquiler asequible" como propiedades por debajo de 750€ mensuales, umbral que delimita el acceso real a vivienda para gran parte de la población. La demanda en este segmento supera ampliamente la oferta disponible, creando un desequilibrio que afecta tanto a inquilinos como a propietarios y administraciones públicas que buscan herramientas más eficientes para gestionar esta problemática.

1.2. Objetivo general del sistema de IA

El objetivo es desarrollar un sistema de Inteligencia Artificial capaz de predecir el precio justo de alquiler de una propiedad basándose en sus características específicas: superficie, ubicación, estado, tipo de vivienda, equipamiento, etc. El enfoque se centra exclusivamente en el rango de vivienda asequible.

Propuesta de valor diferencial:

A diferencia de las plataformas existentes que utilizan filtros estáticos y promedios zonales básicos, este sistema integra un enfoque innovador:

  • Procesamiento inteligente de descripciones: Extracción automática de características implícitas en el texto de anuncios (estado de conservación, luminosidad, equipamiento específico) que las herramientas actuales desaprovechan.
  • Explicabilidad integrada: Cada predicción incluye una explicación clara de los factores determinantes (ubicación, superficie, equipamiento, etc.) y su peso específico en el precio final, promoviendo transparencia y confianza del usuario.
  • Enfoque en equidad: Diseñado específicamente para democratizar el acceso a información sobre precios justos en el segmento asequible y no para favorecer especulación inmobiliaria.
  • Análisis geográfico granular: Identificación de patrones de precio a nivel micro-geográfico (calle/manzana) que revelan oportunidades no evidentes en análisis por distritos.

Líneas de innovación y estudio de negocio:

Funcionalidades de valor añadido que amplían el impacto del sistema:

  • Sistema de alertas inteligentes: Notificación automática cuando una propiedad presente un precio significativamente inferior al valor estimado por el modelo para su zona y características.
  • Visualización interactiva de mercado: Mapas de calor que muestran distribución de oportunidades y zonas con mayor tensión en el mercado asequible.
  • Herramienta de precios éticos: Recomendaciones para propietarios basadas en análisis comparativo de mercado para establecer precios justos según ubicación y características.

Este sistema sirve como herramienta de apoyo para inquilinos en búsqueda activa, propietarios que buscan establecer precios justos, y administraciones públicas que necesitan identificar zonas con problemáticas de acceso a vivienda.

1.3. Justificación del uso de IA y tecnología concreta

¿Por qué los enfoques tradicionales no son suficientes?

El mercado inmobiliario presenta características que hacen inviables los métodos convencionales:

Limitaciones de métodos no basados en IA:

  • Regresión lineal simple: No captura las interacciones complejas entre variables que se influyen mutuamente. El efecto de la superficie varía significativamente según el barrio y tipo de vivienda (ej: 10m² extra valen mucho más en Malasaña que en la periferia).
  • Sistemas de reglas fijas: Requieren actualización manual constante y no se adaptan a los cambios dinámicos del mercado (ej: "ascensor suma 50€" puede ser válido hoy pero obsoleto en 6 meses cuando cambien las tendencias).
  • Promedios zonales: Ignoran las características específicas de cada propiedad, generando estimaciones imprecisas (ej: un bajo sin ascensor no debería valer lo mismo que un cuarto piso con terraza en la misma calle).
  • Filtros estáticos: No identifican interacciones entre variables (ej: parking en centro vs. periferia).

Ventajas específicas del enfoque de IA:

  • Modelado de relaciones no lineales: Algoritmos como Random Forest y XGBoost capturan interacciones complejas entre ubicación, características y precio.
  • Aprendizaje de patrones latentes: Descubrimiento automático de relaciones no evidentes entre variables.
  • Adaptabilidad temporal: Capacidad de reentrenamiento con datos actualizados para mantener relevancia.
  • Procesamiento multimodal: Integración simultánea de datos numéricos, categóricos, textuales y geoespaciales.
  • Escalabilidad operativa: Una vez entrenado, el modelo puede procesar miles de consultas por segundo sin degradar el rendimiento, algo imposible con análisis manual o reglas que requieren cálculos complejos para cada consulta.

Stack tecnológico seleccionado:

  • Random Forest y XGBoost: Para regresión principal, combinando precisión predictiva con interpretabilidad.
  • TF-IDF y Word2Vec: Para análisis semántico de descripciones textuales.
  • DBSCAN y K-means: Para clustering geoespacial y identificación de micro-zonas homogéneas.
  • SHAP y LIME: Para explicabilidad de predicciones, cumpliendo requisitos de transparencia.
  • Pandas y NumPy: Para manipulación y procesamiento de datos estructurados.
  • Folium y Geopandas: Para visualización geoespacial y análisis de patrones geográficos.
  • Scikit-learn: Framework principal para implementación de modelos y pipeline de ML.
  • FAISS: Para búsqueda eficiente de propiedades similares y análisis semántico avanzado en el sistema de recomendación.
  • Google Maps API: Para validación y enriquecimiento de datos geográficos.
  • FastAPI: Para desarrollo de API REST que sirva las predicciones del modelo.
  • Streamlit: Para prototipado rápido y exploración inicial de funcionalidades.
  • Vue.js: Para interfaz de usuario final que consuma la API FastAPI.
  • Docker Compose: Para containerización multi-servicio (API + Frontend).
  • Pytest y FastAPI TestClient: Para testing automatizado de API endpoints y validación de modelos de ML.
  • GitHub Actions: Para CI/CD automatizado con testing, build y despliegue continuo a AWS.
  • AWS (EC2 + S3): Para despliegue en la nube del sistema containerizado.
  • APScheduler: Para automatización tipo cron jobs (reentrenamiento periódico y detección de oportunidades).
  • SendGrid/SMTP: Para sistema de notificaciones por email de alertas y oportunidades detectadas.

1.4. Criterios de éxito

Métricas de rendimiento técnico:

  • Precisión predictiva: Error medio absoluto (MAE) ≤ 50€ en predicciones individuales.
  • Capacidad explicativa: Coeficiente de determinación (R²) ≥ 0.75 en conjunto de test.
  • Eficiencia operativa: Tiempo de respuesta ≤ 2 segundos por consulta.
  • Cobertura geográfica: Predicciones válidas para ≥90% de códigos postales de Madrid.
  • Estabilidad temporal: Degradación del modelo <5% mensual sin reentrenamiento.

Criterios de impacto y usabilidad:

  • Explicabilidad práctica: Cada predicción mostrará los 3-5 factores más importantes (ubicación, superficie, equipamiento, etc.) en términos que cualquier usuario pueda entender.
  • Diferenciación funcional: Ofrecer capacidades que no existen actualmente (análisis automático de descripciones, mapas de micro-zonas, alertas de oportunidades) frente a los filtros básicos de la competencia.
  • Impacto social medible: Demostrar que el sistema ayuda realmente a encontrar vivienda asequible, midiendo feedback de usuarios y tiempo de búsqueda reducido.
  • Transparencia operativa: Ser honesto sobre cuándo el modelo puede fallar y permitir que siempre haya revisión humana de las predicciones importantes.
  • Equidad algorítmica: Verificar que el modelo no discrimine sistemáticamente ciertas zonas o tipos de vivienda, tratando todos los segmentos de forma justa.

Metodología de evaluación:

  • Validación técnica: Hold-out test set (split train/test tradicional) y validación cruzada temporal respetando orden cronológico.
  • Benchmarking comparativo: Comparación de precisión con estimaciones de portales inmobiliarios existentes como Idealista y Fotocasa.
  • Evaluación de usabilidad: Test con usuarios piloto representativos (inquilinos, propietarios y agentes) midiendo facilidad de uso, comprensión de predicciones y satisfacción general.
  • Auditoría de equidad: Verificación de que el modelo no discrimina analizando si los errores de predicción son similares entre diferentes barrios, tipos de vivienda y rangos de precio.

1.6. Evaluación de la situación

Conocimiento previo disponible:

Existe investigación consolidada sobre factores determinantes del precio de alquiler en Madrid: ubicación, superficie, proximidad a transporte público, oferta de servicios locales. Sin embargo, la mayoría de las herramientas digitales actuales aplican esta información de manera básica mediante filtros estáticos que no capturan la complejidad real del mercado ni las interacciones entre variables.

Análisis coste-beneficio:

  • Estructura de costes: Moderados y controlables. El dataset está disponible, el stack tecnológico es conocido y el desarrollo puede realizarse con recursos estándar en un plazo razonable para prototipo funcional siguiendo metodología CRISP-DM.
  • Beneficios esperados: Democratización del acceso a información transparente sobre precios justos, reducción significativa de tiempo de búsqueda para usuarios y posicionamiento diferencial como plataforma centrada en equidad en lugar de especulación.

Requisitos del problema - Perspectiva de negocio:

  • Tiempo de respuesta rápido para mantener una experiencia de usuario fluida.
  • Interfaz intuitiva accesible para usuarios sin formación técnica.
  • Alta disponibilidad del sistema para consultas en línea.
  • Capacidad de actualización periódica del modelo con datos recientes.

Requisitos del problema - Perspectiva técnica:

  • Pipeline de ML end-to-end desde datos crudos hasta predicciones desplegadas.
  • Arquitectura modular que permita actualización independiente de componentes.
  • Logging y monitoreo automatizado de rendimiento del modelo en producción.
  • Capacidad de rollback a versiones anteriores del modelo si degrada.

2. Comprensión de los Datos (CRISP-DM - Fase 2)

2.1. Recopilación inicial de datos

El proyecto utiliza un dataset especializado disponible en Kaggle que recopila anuncios de alquiler en la provincia de Madrid. Los datos provienen de scraping sistemático de portales inmobiliarios principales, proporcionando una muestra representativa del mercado de alquiler actual. Para este proyecto, se aplicará un filtro para seleccionar únicamente propiedades por debajo de 750€ mensuales, eliminando el ruido del mercado premium y centrándose en el segmento asequible de interés.

2.2. Descripción de los datos

El dataset presenta una estructura diversificada que permite aplicar múltiples técnicas de machine learning:

  • Variables numéricas principales: price (variable objetivo en €), size (superficie en m²), rooms (número de habitaciones).
  • Variables categóricas: type (tipología: piso, estudio, ático, dúplex), location (municipio y distrito).
  • Variables binarias: conjunto extenso de características (ascensor, parking, balcón, terraza, amueblado, calefacción, etc.).
  • Contenido textual: descripción completa del anuncio con información detallada sobre estado, equipamiento y características específicas.
  • Información geoespacial: coordenadas geográficas (latitud, longitud) para análisis espacial y clustering.
  • Metadatos del anuncio: URLs, identificadores, fechas de publicación (requieren tratamiento por privacidad).

2.3. Exploración de los datos

Características del volumen y distribución:

  • Volumen: Miles de registros suficientes para entrenamiento robusto de modelos.
  • Cobertura geográfica: Amplia representación de la Comunidad de Madrid con concentración en la capital.
  • Actualidad temporal: Datos contemporáneos que reflejan el estado actual del mercado.
  • Rango de precios: Distribución completa dentro del umbral de 750€ establecido.

Diversidad estructural esperada:

  • Tipologías variadas: desde estudios compactos hasta viviendas familiares dentro del rango asequible.
  • Rango de superficies: distribución desde 25m² hasta 100m² aproximadamente.
  • Distribución geográfica: representación heterogénea entre zonas centrales y periféricas.
  • Equipamiento: amplia variabilidad en características y servicios incluidos.

2.4. Verificación de calidad de datos

Fortalezas identificadas en el dataset:

  • Multimodalidad: Combinación de datos estructurados, texto libre y información geoespacial permite técnicas avanzadas de ML.
  • Autenticidad: Datos reales extraídos de anuncios activos, no sintéticos o simulados.
  • Volumen adecuado: Tamaño suficiente para entrenamiento sin riesgo de overfitting en modelos complejos.
  • Especificidad: Enfoque exclusivo en mercado asequible evita mezcla con segmentos de precio diferentes.

Limitaciones y desafíos identificados:

  • Missing values: Campos opcionales como parking o terraza pueden presentar valores faltantes.
  • Inconsistencias textuales: Variabilidad en formatos, ortografía y estructura de descripciones.
  • Duplicados potenciales: Posible republicación de anuncios o duplicación de propiedades.
  • Sesgo temporal: Snapshot del mercado que puede no reflejar variaciones estacionales.
  • Outliers problemáticos: Propiedades con características excepcionales que podrían distorsionar el entrenamiento.

Estrategia de preparación requerida:

  • Pipeline de limpieza: estandarización de formatos y encoding de caracteres.
  • Tratamiento de missing values: imputación inteligente mediante técnicas apropiadas.
  • Detección de outliers: tratamiento estadístico diferenciando outliers genuinos vs. errores de datos.
  • Preprocesamiento de texto: tokenización, normalización, eliminación de stopwords.
  • Validación geográfica: verificación de coherencia en coordenadas, corrección de errores GPS y completado de campos faltantes mediante APIs de geolocalización.

3. Evaluación legal y ética

3.1. Clasificación de riesgo según Reglamento UE 2024/1689

Análisis sistemático de exclusión de "riesgo inaceptable":

El artículo 5 del Reglamento UE 2024/1689 prohíbe específicamente sistemas de IA de riesgo inaceptable. Se verifica punto por punto que nuestro sistema NO incurre en ninguna práctica prohibida:

Práctica Prohibida (Art. 5) Aplicabilidad Justificación técnica
Técnicas subliminales o manipuladoras NO APLICA Proporciona estimaciones transparentes sin elementos de manipulación psicológica.
Explotación de vulnerabilidades por edad/discapacidad NO APLICA No segmenta usuarios por características protegidas ni explota vulnerabilidades específicas.
Puntuación social por autoridades públicas NO APLICA Evalúa propiedades inmobiliarias, no personas. Sistema no gubernamental.
Identificación biométrica en tiempo real NO APLICA No procesa, almacena ni analiza datos biométricos.
Categorización biométrica sensible NO APLICA Trabaja exclusivamente con características de inmuebles.
Reconocimiento de emociones NO APLICA Análisis limitado a descripciones textuales de propiedades.

Clasificación resultante: El sistema se clasifica como riesgo mínimo.

3.2. Protección de datos y principios éticos

Cumplimiento RGPD: Aunque el dataset no contiene datos personales directos, se implementan medidas preventivas: eliminación de identificadores potencialmente reidentificables (URLs, IDs únicos), anonimización completa de predicciones, limitación de uso a fines académicos e informativos y aplicación de medidas técnicas de seguridad como encriptación de datos, acceso restringido y logs de auditoría.

Principios éticos fundamentales: El sistema se diseña bajo principios de justicia evitando variables discriminatorias, transparencia mediante herramientas de explicabilidad, supervisión humana como herramienta de apoyo no automática y beneficio social priorizando el acceso a vivienda sobre la especulación inmobiliaria.

Las limitaciones identificadas son abordables mediante técnicas estándar de preparación de datos.

Confianza en la ejecución: Tengo experiencia práctica con el ecosistema tecnológico propuesto - desde machine learning y procesamiento de datos hasta desarrollo de APIs y despliegue en la nube. Esta familiaridad técnica, combinada con la solidez de la planificación realizada, me genera confianza en que el proyecto no solo es viable sobre el papel, sino ejecutable de manera eficiente y exitosa.

Preparación para fases siguientes: Con la fundamentación conceptual sólida y la caracterización completa de los datos, el proyecto está preparado para avanzar hacia las fases de preparación de datos y modelado. Los objetivos están claramente definidos, las métricas de éxito establecidas y la estrategia técnica decidida, manteniendo en todo momento los estándares éticos y legales requeridos.
